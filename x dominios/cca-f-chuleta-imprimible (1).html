Multi-agente D1

  • Paralelo = las N Task calls en un mismo turno.
  • Subagente = contexto aislado: todo explícito en la Task call (objetivo, datos, formato, criterio de fin).
  • Fallo a mitad → structured error con categoría, retryable y partial_results. El coordinator decide.
  • Fuentes que discrepan → contested finding con provenance. Nunca promediar.
  • Reporte incompleto y subagentes OK → mirar la decomposition.
  • Hueco concreto → re-delegación targeted, no rebootear.
  • Necesitan hablar constantemente → el corte está mal hecho.
  • Least privilege: cada rol, solo sus tools.

Tools y MCP D2

  • Descripción = interfaz: cuándo usarla, qué devuelve, límites hacia la otra tool, ejemplo.
  • Valores cerrados → enum en el schema, no en la descripción.
  • Resultado enorme → filtro y paginación en la tool: el tool_result entra entero al contexto.
  • MCP = integración reutilizable entre apps; tool local = lógica propia.
  • Primitivos: tools (el modelo actúa) · resources (contexto consultable) · prompts (plantillas).
  • Built-in: de servidor (búsqueda web, ejecución de código) se resuelven solas; de cliente (editor, bash, computer use) las ejecutas tú.
  • Tool que falla → error estructurado como tool_result, no excepción.

Prompting D4

  • Adjetivo ("conservador", "delicado") → condiciones verificables + qué NO cuenta.
  • Prosa inconsistente → 2-4 few-shot con el razonamiento.
  • Retry con feedback específico + tope: arregla formato, estructura, aritmética. No crea datos ausentes.
  • Dato que no está en la fuente → null + resolver en código.
  • Coherencia entre campos → validación semántica en código.
  • Docs largos → varias pasadas acotadas + consolidar en código.
  • Revisar código generado → instancia limpia; reviews grandes → multi-pass.
  • Prefill: controla el arranque, no el resto, y no con extended thinking.
  • temperature 0: reduce sampling, no define criterios.
  • Prefijo largo y estable, muy reutilizado → caching.

Conversacional S7

  • La API es stateless: la memoria la montas tú.
  • Drift dentro del límite de tokens → reinyectar guidelines en breakpoints.
  • Guidelines en system. En user pierden autoridad.
  • Contradicción del usuario → surface & clarify.
  • Petición vaga → preguntar listando los candidatos que ya tienes.
  • Conversación nueva cada N turnos: nunca.

Las 7 formas del distractor

  • Flag inventado — CLAUDE_HEADLESS, --batch, output: summary.
  • Más prosa — reescribir, mayúsculas, bullets.
  • Más recursos — modelo mayor, max_tokens, ventana, temp 0.
  • Over-engineering — classifier, router, fallback entre APIs.
  • Parche — regex, copiar a mano, promediar.
  • Borrón y cuenta nueva — sesión nueva, reiterar todo.
  • Correcto en otro universo — cierto en general, no es el fallo del enunciado.

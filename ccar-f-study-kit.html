How the questions are built

The guide's own sample rationales reveal a small set of distractor recipes. Learn to name them and most questions collapse to two options.

The prompt-only fix where a guarantee is needed

"Enhance the system prompt to state that verification is mandatory." Whenever the failure has financial, security or compliance consequences and a deterministic mechanism exists (hook, prerequisite gate, tool_choice, permission, JSON schema via tool use), the prompt option is the wrong one — it has a non-zero failure rate.

The over-engineered answer before the cheap one is tried

"Train a classifier on historical tickets." "Implement a routing layer that parses input." If the question says first step or most effective and nobody has yet fixed the tool descriptions or added escalation criteria, the infrastructure answer loses. Proportionate response wins.

The feature that does not exist

CLAUDE_HEADLESS=true, --batch, a commands array in .claude/config.json. Know the real flags and paths cold (Cheat sheet) so the invented ones stand out.

Solving a different problem

A routing classifier addresses tool availability when the problem was tool ordering. Sentiment analysis addresses frustration when the problem was case complexity. Ask: does this option touch the mechanism that actually failed?

More capacity as a cure for a structure problem

Bigger context window, higher-tier model, more tokens. Attention dilution, lost-in-the-middle and progressive summarization are not fixed by capacity; they are fixed by restructuring the input (per-file passes, case-facts block, summaries at the top).

Blaming the agent that did its job

When logs show the coordinator decomposed the topic badly, options that tune the search, analysis or synthesis agent are wrong. Read the logs in the stem; they usually name the culprit.

Shifting the burden to humans

"Require developers to split PRs." "Ask the customer to open separate tickets." "Have the customer repeat their details." Almost always a distractor.

Suppress or nuke

Return an empty result marked as success; terminate the whole workflow on one failure; refuse and close the conversation. Both extremes are anti-patterns; the answer is structured error context plus local recovery.

Consensus voting and speculative caching

"Run three passes and keep issues found in two." "Pre-cache what synthesis might need." Consensus suppresses real intermittent findings; speculation cannot predict need. Rarely the answer.

The right tool for the wrong scope

~/.claude/ anything when the team needs it; project scope when it is one person's experiment. Directory CLAUDE.md when files are spread across the tree (use rules with globs instead). Skills when it must load automatically (use CLAUDE.md or rules).

Reading the stem

  • "Most effective first step" — the cheapest change that addresses the root cause. Descriptions before few-shot before routing layers.
  • "Most maintainable" — the mechanism that scales and is version-controlled: rules with globs, project-scoped commands, @import.
  • "Guarantee", "must", "financial", "compliance" — deterministic enforcement (hooks, gates, schemas), never instructions.
  • "Logs show…" — the diagnosis is in the stem. Match the option to what the logs implicate.
  • Percentages in the stem (85% simple / 15% complex) — the answer usually serves the majority case with least privilege and keeps the existing path for the rest.
  • Everything in the Out of scope list (Cheat sheet) is a distractor if it appears as an answer: fine-tuning, embeddings, OAuth details, prompt caching internals, streaming.

The six scenarios

Each scenario frames a block of roughly fifteen questions. Below: the setup as the guide states it, the domains it pulls from, and the reflexes — the handful of correct answers that keep recurring in that scenario. Filter the question bank by scenario to drill each one.

1 · Customer Support Resolution Agent

Agentic ArchitectureTool Design & MCPContext & Reliability

Agent SDK agent handling returns, billing disputes and account issues through custom MCP tools: get_customer, lookup_order, process_refund, escalate_to_human. Target 80%+ first-contact resolution while knowing when to escalate.

  • Ordering that must hold (verify before refund) → programmatic prerequisite gate or tool-call interception hook, never a prompt.
  • Business thresholds (refunds over $500) → PreToolUse-style interception that blocks and redirects to escalate_to_human.
  • Heterogeneous tool output (Unix vs ISO timestamps, numeric codes) → PostToolUse hook normalises before the model sees it.
  • Tool misrouting between similar tools → expand the descriptions (inputs, examples, boundaries) before anything else.
  • Errors → structured: errorCategory, isRetryable, customer-friendly text. Business violations are retriable: false.
  • Escalate when: the customer asks for a human (immediately), policy is silent or needs an exception, no meaningful progress. Not on sentiment, not on self-reported confidence.
  • Multiple customer matches → ask for another identifier, never pick heuristically.
  • Long conversations → persistent case-facts block (amounts, dates, order IDs) outside the summarised history; trim 40-field tool outputs to the 5 that matter.
  • Multi-issue messages → decompose, investigate each in parallel with shared context, synthesise one resolution.
  • Handoff → structured summary (customer ID, root cause, amount, recommended action) because the human has no transcript.

2 · Code Generation with Claude Code

Claude Code ConfigurationContext & Reliability

Team uses Claude Code for generation, refactoring, debugging and documentation. Custom slash commands, CLAUDE.md configuration, and judgement about plan mode versus direct execution.

  • Where things live: .claude/commands/ shared via git; ~/.claude/commands/ personal. Same split for skills and CLAUDE.md. A teammate "not getting instructions" means they live in user scope.
  • Skill frontmatter: context: fork isolates verbose or exploratory output; allowed-tools restricts what the skill may do; argument-hint prompts for missing parameters.
  • Personal variant of a team skill → ~/.claude/skills/ under a different name.
  • Conventions by file type across the tree → .claude/rules/*.md with paths: globs. Directory CLAUDE.md cannot follow scattered files.
  • Monolithic CLAUDE.md → split into .claude/rules/ topic files or @import the standards each package needs.
  • Inconsistent behaviour across sessions → /memory to see which memory files are loaded.
  • Plan mode for architecture, 45+ file migrations, multiple valid approaches. Direct execution for one-file fixes with a clear stack trace. Plan the investigation, execute the implementation.
  • Verbose discovery → Explore subagent returns summaries; /compact when the window fills.
  • Refinement: 2–3 input/output examples beat prose; tests first, then share failures; interview pattern in unfamiliar domains; interacting bugs in one message, independent bugs sequentially.
  • Resuming: --resume <name>; tell it which files changed. If tool results are stale, start fresh with a structured summary.

3 · Multi-Agent Research System

Agentic ArchitectureTool Design & MCPContext & Reliability

Coordinator delegates to web search, document analysis, synthesis and report subagents. Output: comprehensive, cited reports.

  • Hub-and-spoke: all subagent communication goes through the coordinator (observability, error handling, controlled flow).
  • Subagents inherit nothing. Findings go into the subagent's prompt explicitly, as structured data with metadata separated from content.
  • Spawning: Task tool; coordinator's allowedTools must include "Task"; parallel = several Task calls in one response.
  • Coverage gaps with all agents succeeding → the coordinator's decomposition was too narrow. Fix decomposition, then add a refinement loop (evaluate → re-delegate targeted → re-synthesise).
  • Simple queries through the whole pipeline → coordinator selects subagents dynamically by complexity.
  • Duplication → partition scope by subtopic or source type.
  • Tools: scope per role; 4–5 not 18; replace fetch_url with a validating load_document; give synthesis a scoped verify_fact for the 85% simple case.
  • Errors: structured context (failure type, attempted query, partial results, alternatives); local retry for transient; distinguish access failure from a valid empty result; never suppress, never kill the run.
  • Provenance: claim→source mappings preserved through synthesis; conflicting statistics annotated with both sources; publication dates required so time differences are not read as contradictions.
  • Position effects: key-findings summary first, explicit section headers; upstream agents return structured facts, not reasoning chains.
  • Crash recovery: agents export state to a known location; coordinator loads a manifest on resume.

4 · Developer Productivity with Claude

Tool Design & MCPClaude Code ConfigurationAgentic Architecture

Agent SDK agent that explores unfamiliar codebases, explains legacy systems, generates boilerplate and automates repetitive tasks using Read, Write, Edit, Bash, Grep, Glob and MCP servers.

  • Grep searches contents (callers, error strings, imports). Glob matches paths (**/*.test.tsx). Edit needs a unique anchor; when it fails on non-unique text, fall back to Read + Write.
  • Exploration is incremental: Grep for entry points, Read to follow imports. Never read everything up front.
  • Re-exported functions: list the exported names first, then Grep each.
  • MCP config: .mcp.json project-scoped with ${GITHUB_TOKEN} expansion; ~/.claude.json for personal servers; all servers' tools are discovered at connection and available at once.
  • Agent prefers built-in Grep over your MCP tool → make the MCP description explain capabilities and outputs in detail.
  • Standard integrations (Jira) → community server; custom only for team-specific workflows.
  • Exploratory list calls → expose the catalogue as an MCP resource.
  • Open-ended tasks ("comprehensive tests for legacy code") → map, prioritise, adapt as dependencies appear — not a fixed sequence.
  • Divergent approaches from one analysis → fork_session. Continue named work → --resume <name>.
  • Context degradation ("typical patterns" instead of the classes it found) → scratchpad files, subagents for verbose questions, summaries injected between phases.

5 · Claude Code for Continuous Integration

Claude Code ConfigurationPrompt Engineering & Structured Output

Claude Code in the CI/CD pipeline for automated reviews, test generation and PR feedback. Prompts must be actionable and minimise false positives.

  • Non-interactive: claude -p "…" (--print). No --batch, no CLAUDE_HEADLESS.
  • Machine-parseable findings: --output-format json with --json-schema.
  • Project context for CI (testing standards, fixtures, review criteria) → CLAUDE.md, shared with interactive use.
  • Re-runs after new commits → feed prior findings, ask for new or still-open issues only. Duplicate test suggestions → put existing tests in context.
  • Self-review is weak → an independent instance without the generator's reasoning context.
  • False positives: specific categorical criteria (report bugs and security; skip style and local patterns), not "be conservative". Disable a high-FP category temporarily rather than lose trust in all findings. Severity needs concrete code examples per level.
  • Format consistency → 2–4 few-shot examples showing location, issue, severity, fix — and showing acceptable patterns beside genuine issues so it generalises.
  • Dismissed findings → a detected_pattern field so dismissals can be analysed.
  • Large PRs → per-file passes plus one integration pass. Not a bigger model, not smaller PRs, not majority voting.
  • Batches: only for latency-tolerant jobs (overnight debt reports, weekly audits); never pre-merge; no multi-turn tool calling; resubmit failures by custom_id; refine on a sample first.

6 · Structured Data Extraction

Prompt Engineering & Structured OutputContext & Reliability

Extract fields from unstructured documents, validate with JSON schemas, keep accuracy high, handle edge cases, feed downstream systems.

  • Guaranteed shape → tool_use with a JSON schema. Eliminates syntax errors, not semantic ones (totals that don't sum, wrong field).
  • tool_choice: auto may answer in text; any forces some tool (unknown doc type across several schemas); forced {"type":"tool","name":…} runs a specific extractor first, follow-ups in later turns.
  • Fabricated values → make fields nullable/optional. Evolving categories → enum with "other" + detail string, and "unclear" for ambiguity.
  • Inconsistent source formats → normalisation rules in the prompt alongside the strict schema; few-shot showing varied document structures for empty required fields.
  • Retry with feedback: original document + failed output + specific validation errors. Retries cannot recover information absent from the source.
  • Semantic checks: calculated_total beside stated_total; conflict_detected when the source contradicts itself.
  • Batches: 50% cheaper, up to 24 h, resubmit only failed custom_ids (chunk the oversized ones), submission cadence from the SLA.
  • Human review: 97% overall hides bad segments — analyse by document type and field first; field-level confidence calibrated on a labelled set; stratified random sampling of high-confidence output to catch novel errors; route low-confidence and contradictory documents to reviewers.

Rules already banked from your score report

Session termination safeguards

Every session ends in one of exactly two states: a completed resolution, or a handoff to a human. A loop that ends any other way — token limit, iteration cap, unhandled error — routes to escalation rather than falling silent.

Structured handoff packages

Carry accumulated context, findings, and authorization state. The receiver should never need to redo work or re-derive what the agent was permitted to do.

Dynamic subtask decomposition

Subtasks are generated as findings arrive, not fixed up front. A plan that executes the same sequence regardless of what step two discovered is the anti-pattern.

Permissions vs. CLAUDE.md

Anything that must hold regardless of the model's judgment is a settings permission or a hook. CLAUDE.md is guidance the model weighs — right for conventions, wrong for boundaries.

Choosing the configuration mechanism

CLAUDE.md for always-on project context. .claude/rules/ with globs for guidance scoped to matching files. Skills for procedures loaded on demand. Hooks and permissions for anything deterministic.

Providing project context

@ references for a file needed right now. CLAUDE.md for context reusable across sessions. Inline description for a one-off detail.

Structured output method

Strictest compliance is tool use with a JSON schema. Prefilled responses shape the start of a format. Prompt-based formatting is the loosest and wrong when a parser depends on it.

Feedback loops

Capture structured metadata about model errors — what field, what document type, what the correction was — and feed the pattern back into prompts, schemas and few-shot examples.

Out of scope — if it appears as an answer, it is a distractor

  • Fine-tuning or training custom models; embeddings and vector databases
  • Authentication, billing, OAuth, key rotation, rate limits, pricing calculations
  • Hosting or deploying MCP servers; cloud-provider configuration
  • Streaming / SSE implementation; computer use; vision
  • Prompt caching internals (beyond knowing it exists); tokenization details
  • Model internals, RLHF, Constitutional AI; benchmark comparisons
